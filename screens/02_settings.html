Operational Guide
How PromptShield Works

PromptShield evaluates prompt payloads in real time against vector heuristics and policies before reaching LLM endpoints.

arrow_right Read architecture overview

PromptShield operates as an inline defensive reverse-proxy. Payloads undergo multi-tier scanning including embedding tokenization, vector cosine similarity checks against known jailbreak clusters, and rule-based semantic hygiene before forwarding.

Security Decisions
ALLOW
Clean Delivery

Prompt passes heuristics and is routed directly to the AI model unchanged.

BLOCK
Adversarial Interception

Malicious patterns halt immediately with a 403 Security Intercept response.

SANITIZE
Redaction & Neutralization

Identified risk tokens like embedded URLs and sensitive PII are scrubbed prior to dispatch.

ESCALATE
Secondary Review Queue

Borderline signals are asynchronously flagged for security team verification.

arrow_right Decision criteria & fallback policy

Decision thresholds are configured per policy tier in the Policies console. Escalated requests default to fail-safe block if no response is logged within the configured SLA window.

warningKnown Limitations
expand_more
  • Non-standard token encodings require OCR preprocessing before text analysis.
  • Requests exceeding 128k context windows are chunked across inspection workers.
  • Direct API calls bypassing the proxy gateway cannot be monitored or safeguarded.
